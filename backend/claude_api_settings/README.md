# Claude 1차 응답 스키마 설계

실행 계약은 [Preview 설정 계약 v2](../../docs/preview-config-v2.md)에 정리했다. 시스템 프롬프트와 콘텐츠 템플릿은 `uploads.preview_request_v2`가 읽어 신규 Claude 요청에 사용한다. 예시 JSON Schema 파일은 가상 CSV용 참고 자료이며 실제 요청에는 사용하지 않는다.

## 목적과 범위

CSV 한 파일은 단일 테이블로 취급한다. Claude는 제공된 분석 결과에 근거해 **CSV를 어떤 데이터 기반 웹 서비스로 구성할지 판단**하고, 첫 번째 정상 응답에서 템플릿과 컬럼 연결을 완성한다. JSON 설정은 그 판단을 프론트가 실행할 수 있는 형태로 표현한다. Claude는 프론트 코드, 계산식, SQL 또는 CSV의 행 데이터를 생성하지 않는다. 프론트는 검증된 설정과 저장된 CSV 행으로 서비스 화면을 미리 보여준다.

현재 [예시 스키마](preview_output_schema.example.json)는 8개 컬럼을 가진 가상 CSV의 번호와 후보를 넣어 둔 참고 파일이다. 실제 요청에서는 업로드된 CSV를 분석해 각 `enum`을 새로 만든다.

## 첫 번째 호출에 담는 선택

- Claude가 반환하는 모든 **값**은 `enum`으로 제한한다. 화면 제목이나 설명문 같은 자유 문자열은 받지 않는다.
- `views` 배열은 목록 화면의 표시 순서다. 각 원소는 `cards`, `table`, `grouped` 중 하나이며, 템플릿마다 허용하는 속성이 다르다.
- `titleColumn`, `groupColumn`, `badgeColumn`, `imageColumn`, 차트 기준 컬럼, 표시할 컬럼과 그 순서는 모두 첫 번째 응답에서 선택한다.
- `fields`와 `columns` 배열의 순서가 해당 화면의 컬럼 표시 순서다. 비어 있어도 되는 `fields`와 달리 표의 `columns`에는 최소 하나가 필요하다.
- 차트는 현재 `bar` 또는 `donut`, 집계는 `count`만 선택할 수 있다. 값의 집계는 일반 코드가 한다.
- 상세 화면 설정은 응답에서 받지 않는다. 목록이나 표의 행을 열면 프론트가 해당 CSV 행의 **전체 컬럼**으로 상세 화면을 구성한다. 별도 페이지 ID나 화면 간 참조도 필요 없다.
- 화면 제목과 필드 이름은 템플릿 기본 문구와 CSV 컬럼명에서 정한다. 값이 비어 있거나 컬럼명이 없는 경우의 표시 문구도 프론트 규칙으로 정한다.

두 번째 Claude 호출은 기본 흐름에 포함하지 않는다. 향후 enum으로 표현할 수 없는 기능이 꼭 필요할 때만 별도로 검토한다.

## CSV별 스키마 생성

컬럼은 CSV 헤더 순서대로 **1부터 시작하는 정수 번호**를 부여한다. 이 번호와 실제 컬럼 ID의 대응은 백엔드가 보존한다. 스키마의 `allColumns.enum`에는 이번 CSV에 존재하는 번호만 넣는다.

제목·부제·이미지·배지·그룹·차트 기준은 각각 독립적인 후보 enum을 가진다. 후보는 컬럼명, 값의 형태, 결측과 고유값 통계 등 이미 계산한 분석 결과로 결정한다. 확실히 부적합한 후보는 제외하되, 근거가 부족하면 가능한 후보를 남겨 정답을 미리 제거하지 않는다. 따라서 예시 파일의 `[1, 8]` 같은 값은 실제 CSV에 적용하는 고정 규칙이 아니다.

- 필수 역할에 후보가 없다면 사용할 수 있는 후보 범위를 넓힌다. 그래도 구성할 수 없는 템플릿은 `anyOf`의 선택지에서 제외한다.
- 선택 역할에 후보가 없다면 해당 속성을 스키마에서 제거한다. 빈 `enum`을 보내지 않는다.
- 사용 가능한 그룹 기준이 없으면 `grouped`를, 차트 기준이 없으면 `charts` 속성을 제외한다.
- `anyOf`에는 프론트가 실제로 렌더링할 수 있는 템플릿만 넣는다. 새 템플릿이 완성되면 그 템플릿 전용 분기를 추가한다.

## 요청의 `system`과 `messages.content`

[시스템 프롬프트](system_prompt.md)는 모든 호출에 공통인 역할과 판단 기준을 담는다. [콘텐츠 템플릿](content_template.md)은 업로드한 CSV마다 달라지는 분석 결과를 담는다. 두 파일 모두 현재 신규 추론 요청에 연결되어 있다.

콘텐츠 템플릿의 `{{...}}` 표시는 백엔드가 **JSON으로 직렬화한 값**으로 치환한다. 표시 자체를 Claude에 보내지 않는다. 치환 후 `<csv_analysis>` 내부는 유효한 JSON이어야 한다.

- `ROW_COUNT`: 데이터 행 수인 정수.
- `COLUMNS_JSON`: CSV 헤더 순서의 컬럼 배열. 각 항목에 1부터 시작하는 `number`, 원본 `name`, 분석된 자료형과 유형별 개수, 비어 있지 않은 값·결측·고유값의 개수, 관련 경고를 포함한다. 컬럼 번호는 스키마 enum과 정확히 일치해야 한다.
- `WARNINGS_JSON`: CSV 전체의 파싱·분석 경고 배열.
- `SAMPLE_ROWS_JSON`: 소수의 예시 행 배열. 각 항목의 `row_number`와 `values`를 포함하고, `values`는 컬럼 번호순 배열이다. 실제 값과 같은 행 안의 컬럼 조합은 서비스의 주제와 컬럼 역할을 판단하는 중요한 근거이므로 함께 유지한다. 앞부분 행에만 치우치지 않도록 선택 방식도 명시한다.
- `SAMPLING_JSON`: 예시 행의 선택 방식, 최대 행 수, 값 길이 제한, 잘린 위치, 대표 표본 여부를 명시한다.

파싱과 통계는 일반 코드가 수행한다. 전송할 필드와 예시 행 수는 백엔드의 명시적 허용 목록과 상한으로 제한한다. 원본 CSV 전체, 파일 경로, 업로드 ID, API 키는 콘텐츠에 넣지 않는다. 실제 Claude 호출은 전송 범위와 비용을 보고하고 사용자에게 매번 승인받은 뒤 실행한다.

## 배열과 정상화 규칙

Anthropic의 구조화 출력은 `minItems`의 0·1만 지원한다. `maxItems`, `uniqueItems`와 특정 enum 값의 사용 횟수 제한은 이 스키마에 넣을 수 없다. 배열은 간결한 응답과 사용자 지정 표시 순서를 위해 유지한다.

응답 후 일반 코드가 다음 규칙을 결정적으로 적용한다.

1. `fields`와 `columns`의 중복 번호는 **첫 등장만 남겨** 순서를 보존한다.
2. 제목·부제·배지 등 이미 별도 위치에 표시한 컬럼이 `fields`에도 있으면, 같은 값을 두 번 표시하지 않도록 `fields`에서 제외한다.
3. 같은 목적과 설정의 화면 또는 차트가 반복되면 첫 항목만 남긴다. 목적이 다른 화면 조합은 유지한다.
4. 화면·컬럼·차트 배열에 프론트의 표시 상한을 적용한다. 구체적인 상한은 템플릿 UI를 구현할 때 정한다.
5. 번호가 이번 CSV의 컬럼에 대응하는지, 템플릿별 필수 선택이 있는지, 정리 후에도 표의 컬럼이 하나 이상인지 확인한다.

이 단계는 모델에 수정 요청을 보내지 않는다. 안전하게 정리할 수 없는 경우에는 원본 CSV 컬럼으로 만드는 기본 표를 사용한다. 프리뷰 런타임에는 검증·정리된 설정만 전달한다.

## 남은 설계 범위

지도·달력·입력 폼은 각 템플릿의 동작과 데이터 조건이 확정되고 렌더러가 구현될 때 첫 번째 호출 스키마에 추가한다. 차트에 합계나 날짜별 집계가 필요해지면 해당 집계 방식과 입력 컬럼 조건을 함께 정의한다.

JSON Schema의 enum은 **허용된 컬럼을 선택했는지** 제한한다. 그 컬럼이 의미상 가장 적합한지는 별개이므로, Claude에 전달하는 분석 근거와 로컬 검증을 함께 설계해야 한다.
