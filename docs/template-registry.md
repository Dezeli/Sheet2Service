신청·승인은 단순 예약 신청에 사용할 수 있지만 날짜 충돌·정원·가용 시간을 검사하지 않는다. 결제·첨부파일·알림·자유 입력 필드 구성도 현재 지원하지 않는다. 구현됨은 기존 소유 브라우저 세션에서 기본 동작을 제공한다는 뜻이며 외부 사용자 접근·관리자 인증은 후속 범위다.

## 선택과 추천

템플릿은 필요한 유저·관리자 기능을 한 쌍으로 적용한다. 즐겨찾기처럼 관리자 기능이 필요 없는 후보는 향후 단독 기능으로 구현한다. 추천 수에 임의의 3개 제한을 두지 않으며 AI는 CSV와 추천 서비스에 적합한 기능만 선별한다. 전체 템플릿 목록은 내부 지원 기준이며 화면에 자동 추가하지 않는다. 사용자가 직접 추가 요청하면 지원·미구현·미지원을 판단한다. 단계 나열 대신 데이터에 맞는 한 줄 기능 제목을 표시한다.

## 추가 기능 요청

모델 출력 `result.status`는 세 가지 enum이다.

- `supported`: 구현된 템플릿에 맞는 `flow`를 반환한다. 기존 컬럼·템플릿 검증을 거쳐 후보에 추가하며 선택은 사용자에게 맡긴다.
- `unimplemented`: 미구현 템플릿 enum을 반환한다. 서버가 미구현·선택 불가 문구를 만든다.
- `unsupported`: 목록에서 제공할 수 없는 요청이다. 서버가 미지원 안내를 만든다.

거절과 미구현 안내도 정상 호출 결과로 기록한다. 지원하지 않는 요청을 비슷한 구현 템플릿으로 강제로 바꾸지 않도록 요청 계약에 명시한다. 구현 여부·출력 형식은 서버에서 검증하며 자연어 요청의 의미적 적합성 판단은 Claude가 수행한다. 이전 version 1 `flow` 출력은 진행 중 요청·기록과의 호환을 위해 허용한다.

추가 요청은 사용자가 목적·전송 범위·비용을 확인하고 버튼을 누른 1회만 실행한다. 자동 재시도는 없다.
