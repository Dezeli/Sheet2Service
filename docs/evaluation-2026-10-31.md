# 예약 시트 이해 평가 (2026-10-31, 샘플 30장)

공공데이터 포털에서 수집한 예약 관련 CSV 30장을 `ReservationUnderstanding` 호출 1회씩으로 읽혔다(호출 30회, 모델 claude-sonnet-5). 판정은 내가(에이전트) 각 시트의 헤더와 값을 보고 정한 기대값과 비교한 것이며 연구 결과가 아니라 개발 중 점검이다. ModelCall 기록은 DB에 남아 있다(`manage.py model_calls --purpose "예약 시트 이해"`).

## 평가 방식의 한계

- 26장은 파일 이름을 `s01.csv`처럼 익명화해서 보냈다. 프롬프트는 파일 이름을 가장 직접적인 주제 단서로 쓰므로 실제 사용보다 불리한 조건이다. 먼저 돌린 4장(정읍·상주·숲해설·서산)은 영문 설명 이름을 썼다.
- 상한(10MB·50,000행·500,000셀)을 넘는 6장은 앞부분만 잘라 보냈다(안전체험관 45,000행, 휴양림 예약 49,999행, 휴양림 정책 26,052행, 코레일 예약신청 7,388행, 특약정보 30,937행, 인천 시설예약 49,999행, 인천 과학관 49,999행, 나노 장비 45,000행).
- 자르는 과정에서 cp949 파일 4장(안전체험관, 인천 시설예약, 인천 과학관, 나노 장비)의 한글이 깨진 채 전송됐다(내 스크립트 오류). 이 4장의 결과는 구조는 맞췄지만 상태 값·라벨이 깨져 있어 **재실행이 필요**하다.

## 발견한 문제와 조치

1. **단일 대상 시트**(공연 데크 하나, 전시관 하나, 강당 대관)는 대상 컬럼이 없어 예약 기능이 통째로 빠졌다. → 기록형·회차형에서 대상 컬럼이 없으면 `subject` 이름의 대상 하나를 만들어 예약을 받는다(`resources.implicit`).
2. **기록만(record_only)** 판정이면 새 예약을 안 받았다(휴양림). 서비스의 목적상 새 예약은 받아야 한다. → 기록만 시트도 새 예약을 즉시 확정으로 받고, 프롬프트에 `instant`가 보통 더 맞다고 적었다.
3. 서버가 보충한 상태 값이 전부 `other`였다. → 낱말로 뜻을 추정한다(취소·환불→cancelled, 체크아웃·완료→completed 등).
4. 담당자 범위 컬럼으로 **전화번호**가 지정됐다(서울시). → 범위 컬럼 역할을 담당자·기관·대상 묶음·대상·예약자 속성·장소로 제한하고 프롬프트에도 적었다.
5. 시작월일과 시작시간이 둘 다 `start`인 시트(울산시설공단)에서 시간을 버렸다. → 같은 역할의 날짜 컬럼과 시각 컬럼을 합쳐 읽는다.
6. 상주 시트처럼 상태 값이 12종을 넘으면 서버가 상태 값을 검증하지 못한다(미해결, 신호의 값 집합 상한).
7. 대전 예약가능시설의 `접수기간`은 접수 가능 기간인데 `created_at`으로 읽었다(미해결, 역할 어휘에 접수 기간이 없음).
