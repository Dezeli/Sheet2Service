# 서비스 기능 조합

## 선택 화면

2026-10-11 갱신: `/select`의 세 번째 단계에서 대시보드·사용자·관리자 3단으로 선택한다. 연결된 사용자·관리자 항목은 상단 같은 행에 배치하고 연결선으로 표시한다. 각 그룹 안에서는 선택한 항목을 먼저 표시하며 독립 항목은 아래에 배치한다. 목록 조회와 관리자 데이터 관리, 대시보드는 독립 선택이다. 좁은 화면에서는 3단 관계를 유지하며 가로 스크롤한다.

구현된 추천 항목은 기본 선택한다. 신청·승인과 즉시 접수는 추천 순서상 첫 하나만 선택한다. 저장한 설정이 있으면 이를 복원한다. 선택 수는 각 역할의 선택 가능한 최대 기준 `N/M개 선택`으로 표시한다. 이전·서비스 프리뷰 생성 버튼은 내용 박스 바깥 하단에 있다.

원하는 기능 입력 폼은 항상 표시한다. 전송 버튼을 누르면 내부 사전 조회 후 한 번의 모델 요청으로 지원 여부를 확인하며, 별도 확인 화면과 자동 재시도는 없다. 결과 안내는 입력 박스 바깥 아래에 표시한다. 직접 입력 대상은 현재 사용자·관리자이며 대시보드는 후속 작업이다.

- 최신 정상 Claude 제안과 그 이후의 최신 직접 입력 제안을 사용한다. 예전 호출의 후보를 누적하지 않는다.
- 유저·관리자 후보는 호환되는 기능 한 쌍으로 표시한다. 같은 템플릿은 한 번만 표시한다.
- 추천 수에 임의의 제한을 두지 않는다. AI가 선별한 기능만 표시하며 전체 템플릿 목록을 자동 추가하지 않는다. 추가 요구는 직접 입력으로 지원·미구현·미지원을 판단한다.
- 단계 설명 대신 선택한 기능의 짧은 유저·관리자 설명을 표시한다. 직접 입력은 등록된 목록 기준으로 추가 가능·미구현·미지원을 안내한다. 1회 호출 승인은 유지한다.

## 조합 계약

새 UI는 기존 `features`와 함께 `roles: {dashboard: [...], admin: [...]}`를 전송한다. 독립 관리자 선택은 `manage_catalog`, 대시보드는 `csv_statistics`·`request_statistics`·`inquiry_statistics`다. 서버가 연결된 관리자 선택을 합쳐 `role_selection: {dashboard, user, admin}`에 저장한다. 프리뷰 표시가 이를 따른다. 유저 기능이 없어도 독립 관리자/대시보드 기능을 선택할 수 있다. 모두 비어 있는 선택은 거부한다.

`POST /api/uploads/{id}/workflow/`는 `features` 배열을 받는다. 각 값은 `scope: user|admin`, `model_call_id`, `index`로 원래 후보를 참조한다. 서버에서 업로드 소유권·후보·템플릿·컬럼을 검증하고, 대응하는 유저·관리자 구성을 생성한다.

선택 가능한 기능은 신청·승인, 즉시 접수, 문의 접수, 목록 보기, 일정·정원 예약, 공지, 대여·반납, 견적 요청이다. 신청·승인과 즉시 접수는 동일 접수 기능의 대체 모드이므로 하나만 선택한다. 예약·공지·대여·견적은 별도 기능이며 다른 기능과 함께 사용할 수 있다. 중복 기능과 승인 모드 충돌은 서버에서도 거부한다.

저장 설정은 기존 version 1의 `user`·`admin`을 유지하면서 `modules` 배열에 선택한 각 설정과 `selection` 참조를 저장한다. 기존 단일 설정과 기존 `{user, admin}` 선택 API도 계속 지원한다.

## 실행

User에서는 선택한 기능을 메뉴로 전환한다. Admin은 데이터 관리와 선택한 접수·문의 기능을 제공한다. Dashboard는 선택한 접수·문의 집계와 CSV Preview를 함께 표시한다.

문의·접수 API는 해당 모듈의 구성을 찾아 실행한다. 선택 순서에 관계없이 함께 작동한다. 문의 기능을 해제해도 기존 문의 데이터는 삭제하지 않으며 다시 선택하면 조회할 수 있다.

구성 저장, 메뉴 전환, 문의·신청 처리에는 Claude를 호출하지 않는다. 현재 접근 권한은 기존 업로드 소유 브라우저 세션 범위를 유지한다.
