# CSV 업로드·기본 분석 API

React에서 CSV 파일·인코딩 선택, 업로드, 앞 20행 미리보기, 긴 셀 펼치기, 원본 다운로드와 컬럼별 분석 표를 제공합니다. 분석 표에는 타입 후보, 결측 수·비율, 고유값 수, 숫자·날짜 비율, 값 형식별 개수와 확인 사항을 표시합니다. Claude API는 사용하지 않습니다. 화면 새로고침 시 결과를 복원하는 기능은 아직 없습니다.

## 입력과 보존

- 쉼표로 구분한 CSV만 받습니다. 첫 레코드는 컬럼명입니다.
- `encoding`: `auto` (기본값, UTF-8 BOM 지원 후 CP949 시도), `utf-8-sig`, `euc-kr`, `cp949`.
- 자동 선택은 디코딩 성공 여부를 기준으로 합니다. 다른 인코딩을 확정적으로 탐지하지 않으므로 한글이 잘못 보이면 인코딩을 지정해야 합니다.
- 기본 화면은 자동 인코딩이며 수동 선택은 고급 설정에 있습니다. 자동 모드는 엄격한 디코딩이 모두 실패하면 UTF-8·CP949 중 해석 불가 바이트가 가장 적은 후보를 사용하되, 비ASCII 바이트 대비 오류가 0.1% 이하일 때만 `�`로 대체합니다. UTF-8 BOM이 있으면 복구 후보를 UTF-8로 한정합니다. 이는 휴리스틱이며 언어 의미를 판별하지 않습니다.
- 수동 인코딩은 기본적으로 해석 불가 바이트를 거절합니다. `allow_replacement`를 지정하면 대체를 허용합니다. multipart에서는 `"true"`, 재분석 JSON에서는 `true`를 사용합니다. 대체 바이트 수는 `analysis.source.replaced_bytes`와 경고에 표시하며 원본 파일은 변경하지 않습니다. 대체된 값의 통계와 고유값에는 손실이 있을 수 있습니다.
- Excel에서는 CSV UTF-8로 내보내기를 권장합니다. 내보내기 전에 앞자리 0, 날짜, 수식 결과가 의도한 값인지 확인합니다.
- 원본 바이트는 `backend/media/originals/`에 보존합니다. DB에는 업로드 정보와 버전 있는 분석 JSON을 따로 저장합니다. 파일 내용은 Git에 포함되지 않습니다.
- 현재 한도: 파일 10MB, 데이터 레코드 50,000개(빈 행 포함), 200열, 비어 있지 않은 레코드 기준 500,000셀, 셀 문자열 100,000자. 동기 분석이며 대용량 작업 큐와 자동 삭제는 아직 구현하지 않았습니다.

## 호출 흐름

동일한 브라우저 세션의 쿠키를 유지합니다. POST에는 `/api/session/` 응답의 `csrf_token`을 `X-CSRFToken` 헤더로 전달합니다.

| 요청 | 내용 |
| --- | --- |
| `GET /api/session/` | 브라우저 세션 시작, CSRF 토큰 발급 |
| `POST /api/uploads/` | multipart의 `file`, `encoding`을 받아 저장·분석 (201) |
| `GET /api/uploads/{id}/` | 저장된 업로드 정보와 분석 결과 |
| `POST /api/uploads/{id}/` | JSON `{"encoding":"cp949"}`로 원본 재분석 |
| `GET /api/uploads/{id}/original/` | 받은 바이트 그대로 원본 다운로드 |

다른 브라우저 세션에서는 조회·재분석·다운로드할 수 없습니다. 세션 만료 후 복원과 계정 기반 관리는 후속 범위입니다. 실패한 업로드는 저장하지 않고, 재분석 실패는 기존 결과를 유지합니다.

## 분석 규칙

- 모든 CSV 셀은 문자열로 보존하며 형변환하지 않습니다. 숫자·날짜 비율은 해석 가능 여부만 계산합니다. ISO 형식 날짜·날짜시간, 숫자, 시간, 수식 모양 문자열, 텍스트를 구분합니다.
- 빈 문자열·공백만 있는 셀은 통계에서 결측으로 취급하지만 미리보기에는 원래 문자열을 남깁니다. `NULL`, `N/A` 같은 값은 임의로 결측 처리하지 않습니다.
- 고유값은 결측을 제외한 원본 문자열 기준입니다. 숫자·날짜 비율의 분모도 결측을 제외합니다.
- 앞자리 0을 가진 정수 문자열은 숫자로 해석 가능하더라도 텍스트 후보로 유지합니다. 후보는 엔티티·의미·업무 규칙에 대한 판단이 아닙니다.
- 중복·빈 컬럼명은 그대로 두고 위치별 `column_1` 등의 ID와 임시 표시 이름을 제공합니다.
- 행 너비가 다르면 추가 컬럼을 보존하고 부족한 위치만 `null`로 표시합니다. 완전히 빈 데이터 레코드는 통계와 미리보기에서 제외합니다.
- 미리보기는 앞 20개 데이터 레코드입니다. API의 `row_number`는 헤더를 1로 세는 CSV 논리 레코드 위치입니다. 화면에서는 1을 빼서 컬럼명을 0행, 첫 데이터를 1행으로 표시합니다. 따옴표 안 줄바꿈이 있는 경우 물리적인 줄 번호와 다릅니다. 제외된 빈 레코드의 위치는 건너뜁니다.
- 수식 문자열은 실행하지 않습니다. 결과에 원본 내용이 포함되므로 화면은 텍스트로 렌더링해야 합니다.

## 검증

```sh
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py test uploads
```

테스트는 합성 CSV로 인코딩, 쉼표·줄바꿈, 식별자 보존, 결측·혼합 타입, 잘못된 입력, 원본 다운로드, 세션 격리와 CSRF를 확인합니다. 사용자 예시 CSV 전체를 읽지 않습니다.
