# 공통 접수 템플릿 v1

신청·승인과 즉시 접수는 같은 CSV 항목 선택·신청 내용·접수 데이터·관리 목록을 사용한다. 분야별 예약 규칙은 포함하지 않는다. 접수 데이터는 CSV와 별도 `ServiceRequest`로 저장한다.

## 설정

`reception.template`은 `reception`이며 `reception.approval` enum은 `required` 또는 `none`이다. 기존 플로우 enum과 호환되도록 아래 쌍을 사용한다.

| 모드 | 유저 enum | 관리자 enum |
| --- | --- | --- |
| 승인 필요 | `request_review` | `review_requests` |
| 즉시 접수 | `request_auto` | `monitor_requests` |

`subjectColumn`은 신청할 CSV 항목을 표시하는 1부터 시작하는 컬럼 번호다. 제출 양식은 항목과 선택적 신청 내용(최대 5,000자)으로 고정한다. 자유 형식 필드 생성은 지원하지 않는다.

## 상태와 동작

- 승인 모드: `pending` → `approved` → `in_progress` → `completed`. 대기 중에는 `rejected`로 거절할 수도 있다.
- 즉시 접수: `submitted` → `in_progress` → `completed`.
- 작성자는 대기·접수·승인 상태에서 `cancelled`로 취소할 수 있다. 처리 시작 후 취소는 지원하지 않는다.
- 거절 사유는 필수다. 다른 처리 단계의 메모는 선택 사항이며 최신 처리 메모를 저장한다. 변경 이력은 아직 제공하지 않는다.
- 같은 사용자 세션·항목에 진행 중인 접수가 있으면 중복 제출을 막는다. 거절·취소·완료 후에는 새로 접수할 수 있다. 제출 시 업로드 잠금을 사용해 동시 중복 제출을 방지한다.
- 요청별 승인 모드를 저장하므로 이후 서비스 설정을 바꾸어도 기존 요청의 처리 규칙은 보존된다.
- CSV 행이 삭제돼도 항목명 스냅샷과 신청 내용은 남는다.

사용자·관리자 목록은 20건씩 조회한다. 새로고침으로 처리 결과를 조회하며 Dashboard는 모든 접수 상태를 집계한다. 각 단계에서 Claude를 호출하지 않는다.

## 확인

기존 플로우 선택 화면의 기본 후보에서 `신청 후 승인`과 `신청 승인·거절`, 또는 `신청 즉시 접수`와 `신청 현황 관리`를 선택한다. 기본 후보 선택은 추가 Claude 호출 없이 가능하다.

현재 접근 범위는 업로드 소유 브라우저 세션이다. 별도 사용자 접근·관리자 인증, 사용자 지정 입력 필드, 알림과 파일 첨부는 후속 범위다.
