# 공지 템플릿 초안

`notice`(사용자)와 `manage_notices`(관리자)는 연동 선택한다. CSV에 공지 내용이 있다고 가정하지 않고 별도 Notice 테이블에 운영 안내를 저장한다. 도메인과 CSV 컬럼명은 고정하지 않는다.

## 동작

- 관리자는 제목·본문을 작성하고 미게시로 저장하거나 바로 게시한다. 기존 공지의 내용·게시 상태를 수정할 수 있다.
- 사용자는 게시된 공지만 목록과 펼친 본문으로 확인한다. 게시 해제하면 사용자 목록·상세에서 즉시 제외된다.
- 게시 시각을 기록한다. 게시 중 내용 수정은 게시 시각을 유지하고, 게시 해제 후 다시 게시하면 새 게시 시각을 기록한다.
- 공지 기능을 해제해도 데이터는 삭제하지 않으며 다시 선택하면 복원된다. 다른 선택 기능과 함께 실행할 수 있다.
- 제목은 1~120자, 본문은 1~10,000자다. 일반 텍스트로 표시하며 HTML을 실행하지 않는다.

## API

`/api/uploads/{id}/notices/`의 GET은 게시된 공지를 페이지당 20개 반환한다. 기존 소유 세션의 관리자 Preview는 `admin=1`로 미게시 공지도 조회한다.

- POST: `{title, body, is_published?}`. 기본은 미게시다.
- GET `/{notice_id}/`: 게시된 공지 상세. 관리자 Preview는 `admin=1` 사용.
- PATCH `/{notice_id}/`: 제목·본문·게시 여부 중 변경할 값만 전달한다.

소유 업로드 세션과 공지 모듈 선택을 검사한다. 쓰기는 CSRF 검증과 결정적 필드 검증을 적용한다. 기존 Preview와 같이 사용자·관리자는 업로드 소유 브라우저 세션 안의 화면이다. `admin=1`은 표시 모드이며 관리자 인증 수단이 아니다. 외부 사용자 공개와 계정별 권한은 후속 범위다.

AI는 등록된 템플릿에서 공지가 필요한 서비스를 판단하여 추천한다. 새 공지 템플릿을 전체 목록으로 자동 추가하지 않는다. 사용자 직접 요청도 등록된 지원 범위로 판단하며 작성·수정·조회에는 모델을 호출하지 않는다.

삭제·예약 게시·첨부파일·알림·조회수·상단 고정은 이번 초안 범위에서 제외한다. 다음 템플릿은 대여·반납이다.
