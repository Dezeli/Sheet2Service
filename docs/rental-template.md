# 대여·반납 템플릿 초안

`rental`과 `manage_rentals`를 연동 선택한다. CSV는 대여할 항목의 목록이며 재고와 대여 신청은 별도 RentalStock·Rental 테이블에 저장한다. 물품 이름이나 특정 분야의 CSV 컬럼을 고정하지 않는다.

## 지원 범위

- 관리자: CSV 항목별 총 재고 등록·변경, 신청 접수 중지·재개, 승인·거절, 대여 시작, 전량 반납, 처리 메모.
- 사용자: 가능한 수량 조회, 항목·수량과 선택 신청 내용 제출, 내 신청 상태 조회, 대여 시작 전 취소.
- 기본 입력: 재고 0~10,000, 신청 수량 1~10,000의 정수. 신청 내용·처리 메모는 최대 2,000자.
- 같은 항목의 진행 중 신청은 세션당 하나만 허용한다. 이전 요청이 취소·거절·반납된 뒤 새로 신청할 수 있다.

## 재고와 상태

신청은 재고를 확보하지 않는다. 현재 가능한 수량보다 많은 신규 신청은 거부하지만 서로 다른 사용자의 승인 대기 신청이 경쟁할 수 있다. 화면에서도 승인 시 수량이 확보됨을 안내한다.

승인 시점에 재고를 다시 확인하여 수량을 확보한다. `approved`와 `loaned` 수량의 합을 확보 수량으로 계산하며 별도 증감 카운터를 쓰지 않는다. 업로드 행 잠금으로 승인·반납·재고 변경 등을 직렬화하여 동시 승인 초과를 방지한다.

| 현재 상태 | 관리자 처리 | 사용자 처리 | 재고 확보 |
| --- | --- | --- | --- |
| 승인 대기 | 승인·거절 | 취소 | 없음 |
| 승인 | 대여 시작 | 취소 | 있음 |
| 대여 중 | 전량 반납 | 없음 | 있음 |
| 거절·취소·반납 | 없음 | 새 신청 가능 | 없음 |

같은 처리를 반복하거나 순서를 건너뛰면 거부한다. 총 재고를 확보 수량보다 줄일 수 없다. 접수 중지나 원본 항목 삭제 후에는 신규 신청·승인을 막지만 이미 승인된 건의 대여 시작·반납 처리는 허용한다. 항목 이름과 내역은 보존한다.

## API

`/api/uploads/{id}/` 아래에 있으며 소유 세션·선택된 대여 모듈·CSRF를 검사한다.

| 경로 | 동작 |
| --- | --- |
| `rental-stocks/` | GET 재고 목록, POST `{row_id, total}` 등록 |
| `rental-stocks/{id}/` | PATCH `{total?, active?}` 변경 |
| `rentals/` | GET 신청 목록, POST `{stock_id, quantity, content?}` 신청 |
| `rentals/{id}/` | PATCH `{status, processing_note?}` 상태 처리 |

목록은 페이지당 20개다. 사용자 재고 목록은 `available=1`로 접수 중이며 원본이 있는 항목만 조회한다. 본인 신청은 `mine=1`을 사용한다. 취소 요청은 본인 세션 여부를 검사하며 관리자 메모를 수정할 수 없다.

## 후속 범위

기존 Preview처럼 업로드 소유 브라우저 세션 안에서 사용자·관리자 화면을 시연한다. 외부 사용자 공개·계정별 역할 인증은 아직 없다. 현재 신청자 구분은 브라우저 세션 기준이다.

기간별 예약·대여 기한·연체 처리·부분 반납·개별 물품 번호·요금·보증금·결제·알림은 지원하지 않는다. AI에는 이 구현 범위를 전달하고 적합한 CSV나 추가 요청에만 추천하도록 한다. 재고·대여 처리에는 모델을 호출하지 않는다. 다음 초안 후보는 견적 요청이다.
