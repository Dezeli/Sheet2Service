# 작업 인수인계 (2026-09-14)

## 사용자와 합의한 작업 방식

- 작업을 작고 검토 가능한 단위로 나누고 각 단위가 끝나면 피드백을 받습니다. 다음 기능을 임의로 연속 구현하지 않습니다.
- 브라우저 확인은 사용자가 직접 합니다. 브라우저 자동화·스크린샷 검증을 요청 없이 하지 않습니다. 필요한 최소 테스트·빌드만 실행하여 토큰을 아낍니다.
- 커밋은 변경과 메시지를 제안하고 승인 후 진행합니다. 이번 CSV 기능과 정리 문서 커밋은 사용자가 명시적으로 승인했습니다.
- Git에 설정된 사용자 작성자 정보를 사용하고 AI author/co-author/contributor 표기를 넣지 않습니다.
- 푸시는 사용자가 마지막에 직접 합니다. 자동 push 금지.
- Claude API 연동은 비용 때문에 최대한 미룹니다. 현재 호출 없음.

## 프로젝트 목표와 확정 사항

평면적인 업무 표에서 의미·엔티티·관계·기능을 추론해 실제 웹 서비스 형태의 임시 Preview를 구성합니다. 정규화를 선호하되 불확실한 의미는 임의 확정하지 않고 필요한 부분만 사용자에게 확인합니다.

- Django + DRF, React + Vite, PostgreSQL, Docker Compose.
- 처음에는 XLSX가 기본이었지만 사용자가 **초기 입력을 CSV 전용**으로 단순화했습니다. XLSX·시트 선택은 구현하지 않습니다.
- 일반 코드로 파싱·검증·통계를 처리하고 Claude는 추후 의미·구조 추론 계층으로만 사용합니다.
- 임의 코드 생성보다 검증된 통합 템플릿과 설정으로 서비스 Preview를 구성할 계획입니다.
- 원본·분석·데이터 모델·관계·기능/UI·업무 규칙을 Preview와 분리해 관리합니다. 향후 Export에 재사용할 수 있어야 합니다.
- 초기에는 소수 Preview의 안정성을 우선하고, 약 24시간 만료를 고려합니다. Export·대규모 운영은 초기 범위가 아닙니다.

## 현재 구현

작업 브랜치: `feat/xlsx-upload-analysis` (생성 후 CSV 전용으로 범위가 바뀌었으며 브랜치명은 유지).

- CSV 업로드, 원본 바이트 파일 저장, PostgreSQL 업로드 메타데이터·분석 JSON 저장.
- 브라우저 세션별 조회·재분석·원본 다운로드, POST CSRF 검사.
- UTF-8 BOM 포함 UTF-8 → CP949 엄격 디코딩 순서로 자동 선택. 수동 설정은 고급 설정 안에 숨겨둡니다.
- 모두 실패하면 해석 불가 바이트가 적은 후보를 선택하되 비ASCII 바이트 대비 오류 0.1% 이하일 때만 `�`로 대체합니다. 대체 개수·통계 영향 경고 표시, 원본은 변경하지 않습니다. 상세 규칙은 `csv-upload-api.md` 참고.
- 컬럼명·원본 값 보존. 중복/빈 컬럼명은 위치 ID로 구분. 결측·고유값·타입 후보·숫자/날짜 비율·확인 사항 계산.
- 앞 20행 미리보기, 긴 설명문 펼치기, 원본 다운로드, 업로드 진행/오류 표시.
- 미리보기 아래 컬럼별 분석 표: 타입 후보, 결측 수/비율, 고유값 수, 숫자/날짜 비율, 값 형식 개수와 확인 사항. 실제 전체 레코드 통계이며 미리보기 20행만 분석한 것이 아닙니다.
- 사용자 요청에 따라 화면에서 헤더 0행, 첫 데이터 1행. 저장된 API `row_number`는 헤더 1 기준을 유지하고 화면에서 1을 뺍니다. 완전히 빈 레코드는 생략하므로 번호가 건너뛸 수 있습니다.

핵심 파일:
- `backend/uploads/analysis.py`: 독립적인 일반 코드 기반 CSV 파싱·프로파일링.
- `backend/uploads/models.py`, `views.py`, `urls.py`, `migrations/0001_initial.py`: 저장·API.
- `backend/uploads/tests.py`: 합성 CSV·DB/API 테스트.
- `frontend/src/main.jsx`, `style.css`: 업로드·미리보기·분석 표.
- `docs/csv-upload-api.md`: API 계약, 한도, 분석 규칙.

## 검증과 로컬 환경

- Docker 엔진·3개 서비스 실행, PostgreSQL 연결·마이그레이션 완료를 확인했습니다.
- 초기 WSL 설치 손상으로 Docker가 실패했으나 사용자가 WSL 복구·업데이트 후 해결했습니다. BIOS 문제가 확정된 것이 아닙니다.
- 프론트엔드 빌드와 백엔드 테스트 통과. 브라우저는 사용자가 업로드·미리보기 동작을 확인했고, 가장 최근 추가한 컬럼별 표는 사용자 확인을 기다리는 상태입니다.
- Windows bind mount에서 Vite가 파일 변경을 감지하지 못한 적이 있어 변경 반영 시 `docker compose restart frontend`를 사용했습니다. 폴링 설정 변경은 하지 않았습니다.
- 현재 세션 PATH에서 Docker가 안 잡히면 다음 실행 파일을 사용합니다:
  `C:\Users\ediso\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe`
- PowerShell에서 `npm` 실행 정책 오류가 나면 `npm.cmd` 사용.
- 작업 디렉토리: `C:\Dev\Free\Sheet2Service`.
- 웹: http://localhost:5173, API health: http://localhost:8000/api/health/.
- 개발 실행: `docker compose up --build -d`.
- `.env`, `.venv`, `node_modules`, 원본 media, DB 볼륨은 커밋 대상이 아닙니다.

## 예시 파일 관련 맥락

사용자가 `C:\Dev\Free`에 서울시 체육시설 공공서비스예약 CSV를 제공했습니다. 저장소로 복사하거나 커밋하지 않았습니다. 처음에는 형식만 참고하라고 했으므로 파일 전체 내용을 출력하거나 분석 자료로 소비하지 않습니다.

24열에 서비스 ID·분류·서비스명·상태·결제방법·장소·좌표·기간·지역·URL·긴 안내문·전화번호 등이 있습니다. 대부분 CP949로 읽히지만 전체 바이트 유효성 검사에서 CP949 해석 불가 바이트 38개를 확인했습니다. `예약확인서는` 문구 주변에는 실제 역슬래시(0x5C)가 아니라 0x82 뒤 작은따옴표가 있었습니다. 사용자가 동일 제공처 JSON과 CSV의 차이를 언급했으며, 직접 변환한 파일은 아닙니다. 정확한 발생 경위는 미확인이고 **사용자가 사소하니 넘어가자고 했으므로 추가 조사하지 않습니다.**
