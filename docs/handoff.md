# 작업 인수인계

## 2026-09-27 업데이트

- 사용자 화면 확인에서 전체 행 보기의 그래프가 현재 페이지 20행만 집계하는 문제가 확인됐다. 그래프는 같은 세션의 원본 CSV 전체를 서버에서 집계한 결과를 사용하고, 목록은 20행 페이지를 유지하도록 수정했다. 전체 행 보기에서 그래프 집계는 Claude API를 호출하지 않는다.
- 이후 사용자 요청으로 브라우저에서 **원본 CSV 전체를 로컬 분석**하고, Claude에는 앞·중간·뒤 각 2행과 네 구간에서 분산 추출한 4행, 최대 10개 예시 행만 보내도록 변경했다. 이 요청은 이전의 5행만 사용한 **단일 호출** 범위와 구분한다. 새 Claude API 호출 승인은 아직 없다. [현재 CSV 전송 예시](claude-api-preview-example.md)에 실제 로컬 수치를 정리했다.
- 서비스 Preview는 앞 20행을 먼저 보여주고, `전체 행 보기` 버튼으로 저장된 CSV의 모든 데이터 행을 20행씩 탐색한다. 페이지 조회와 전체 그래프 집계는 Claude 토큰을 쓰지 않는다. 루트 예시 CSV를 로컬에서 분석한 결과 697행·24열, 10개 예시 행, 요청 본문 22,516바이트였으며 실제 새 모델 호출은 하지 않았다.
- 사용자가 이번 검증에서 루트 예시 CSV의 **앞 5개 데이터 행만** 사용하도록 지정하고, 목적·전송 범위·모델·1회 호출·예상 비용을 보고받은 뒤 Claude API 1회 호출을 승인했다. 추가 호출·재시도 승인은 없다.
- 승인된 `claude-sonnet-5` v2 호출은 `ModelCall` ID `ba21af0d-da80-406a-80cd-f9d3cf8ca945`, 제한된 업로드 ID `26b9ef6c-f738-4213-89eb-abfa36368906`으로 기록됐다. HTTP 200, 입력 8,464토큰·출력 431토큰, 정규화/검증 통과, 기본 표 대체 없음. 공식 단가 $2/$10 per million tokens 기준 추정 비용은 약 US$0.021이다.
- 모델은 카드 목록 1개를 선택했다. 제목 `서비스명`, 부제 `장소명`, 이미지 `이미지경로`, 배지 `서비스상태`, 필드 `소분류명`·`결제방법`·`지역명`·`전화번호`, 상태별 막대 차트와 결제방법별 도넛 차트다. 앞 5개 행 기준의 선택이며 전체 파일의 의미나 분포를 검증한 결과는 아니다.
- 사용자가 브라우저에서 업로드·서비스 Preview 동작을 확인했고, 전체 행 보기의 그래프가 20행만 집계하던 문제를 발견했다. 서버의 전체 행 집계로 수정한 뒤 화면 재확인은 사용자에게 맡겼다. 새 모델 호출에는 새 승인과 전송 범위 검토가 필요하다.
- 신규 추론 요청과 Preview 연결은 [v2 계약](preview-config-v2.md)으로 전환했다. 아래 2026-09-15 기록의 v1 출력·앞 5행 설명은 당시 상태다.
- CSV 분석은 앞 20행 Preview와 파일 전체에서 선택한 최대 10개 추론 예시 행을 별도로 보관한다. 기존 업로드에 `inference_samples`가 없으면 v2 요청은 재분석 또는 재업로드를 요구한다.
- v2 응답은 중복을 정리하고 검증한다. 유효하지 않으면 전체 컬럼 기본 표를 반환하며 오류와 원본을 호출 기록에 보존한다.
- 최신 코드 검증은 Docker 백엔드 53개 테스트, 프론트 설정 11개 테스트, 프론트 빌드와 `git diff --check`를 통과했다. 브라우저 확인은 사용자 몫이다.
- 전체 행 그래프 집계를 수정했다. 이후 브라우저에서 실제 그래프가 전체 697행 기준으로 보이는지 사용자의 재확인이 필요하다.

- 카드 목록·상세 초안은 사용자가 긍정적으로 평가했습니다. 이후 막대·도넛 그래프, v2 표·그룹 목록, 전체 행 보기가 구현되었습니다.
- 다음 작업은 사용자의 전체 행 그래프 화면 재확인 결과를 받는 것입니다.
- 템플릿과 기능을 먼저 구현하고, Claude는 의미·기능 추론과 템플릿 선택만 담당하는 방향입니다.
- API 호출 승인은 모두 소진되었습니다. 새 호출·재시도는 반드시 별도 승인이 필요합니다.

## 작업 방식과 정책

- 작은 단위로 구현하고 피드백을 받습니다. 문서는 당일 작업 종료 시 일괄 정리합니다.
- 브라우저/UI 검증은 사용자가 직접 합니다. 요청 없이 자동화·스크린샷 검증을 하지 않습니다.
- 커밋은 변경 내용과 메시지를 제안하고 승인 후 진행합니다. AI author/co-author 표기를 넣지 않습니다. 2026-09-27 현재 요청에서는 사용자가 커밋과 푸시를 명시적으로 승인했습니다.
- Claude 키 호출은 매번 목적·전송 내용·모델·횟수·예상 비용을 보고하고 승인 후 실행합니다. 테스트·재시도·자동 호출도 포함합니다.
- 각 모델 호출은 독립적입니다. 현재 입력만 전달하고 이전 대화나 DB 응답은 자동으로 전달하지 않습니다.
- 호출 입력·응답·오류·사용량은 DB에 저장합니다. 중복 차단·캐시 재사용·자동 재시도는 구현하지 않습니다.
- 실제 모델 테스트는 사용자가 제공한 예시 CSV를 사용합니다. 단위 테스트용 합성 fixture와 실제 호출을 구분합니다.

## 목표와 역할 분담

CSV → 일반 코드 분석 → Claude의 의미·기능 추론 및 템플릿 선택 JSON → 검증 → 템플릿 조합으로 웹 Preview 제공.

- Django + DRF, React + Vite, PostgreSQL, Docker Compose. 초기 입력은 CSV 전용입니다.
- 파싱·검증·통계·패턴 계산과 차트 집계는 일반 코드가 담당합니다. Claude에 통계 재계산을 맡기지 않습니다.
- 사용자는 원시 데이터를 많이 보내기보다 앞단에서 필요한 근거를 분석·요약해 전달하길 원합니다.
- 재사용 가능한 화면·기능 템플릿을 구현하고 Claude는 선택과 컬럼 연결만 하게 합니다. 임의 코드·SQL 생성은 금지합니다.
- 원본·분석·데이터 모델·관계·설정은 Preview 실행 환경과 분리합니다.
- 새로고침 결과 복원은 사용자가 불필요하다고 판단해 보류했습니다.

## 구현 현황

### CSV와 키

- CSV 업로드·원본 바이트 보존·PostgreSQL 메타데이터/분석 JSON 저장, 세션 격리, 재분석, 다운로드, CSRF가 구현되어 있습니다.
- 루트 `.env`의 `ANTHROPIC_API_KEY`를 Django 백엔드만 읽습니다. `.env`·`.env.*`는 Git 제외되고 `.env.example`만 추적됩니다.
- 루트 사용자 CSV는 `/*.csv`, 업로드 파일은 `backend/media/`로 Git 제외됩니다.

### 호출 기록

- `backend/uploads/models.py`의 `ModelCall`, `0002_modelcall` 마이그레이션, `call_records.py`를 추가했습니다.
- 요청 본문, 승인 기록, 응답 원문, 파싱 결과, 검증 오류, HTTP 상태, 요청 ID, 토큰 사용량, 소요 시간, 오류를 저장합니다. API 키·인증 헤더는 마스킹합니다.
- `manage.py model_calls`로 목록/상세 조회할 수 있습니다. 공개 조회 API/UI는 아직 없습니다.

### 추론 계약

- `backend/uploads/inference.py`: 분석 결과에서 입력을 만들고 프롬프트·응답을 검증합니다.
- `inference_schema.py`: Claude `output_config.format`의 JSON Schema입니다. 정상 응답은 정해진 JSON 구조로 강제됩니다.
- 현재 출력은 요약·엔티티·관계·확인 질문 후보입니다. **Preview 설정 JSON과는 아직 연결되지 않았습니다.** 템플릿 규격을 확정한 뒤 출력 계약을 바꿔야 합니다.
- 호출마다 새 컨텍스트를 사용합니다. 저장된 과거 응답은 모델에 자동 전달하지 않습니다.
- 단일 JSON/코드 블록은 처리하지만 설명문 속 JSON 추출이나 내용 자동 복구는 하지 않습니다.

### Preview와 그래프

- `frontend/src/preview/config.js`: 7개 템플릿 ID와 설정 검증, 시설 CSV 예시 설정, 앞 5행 데이터 어댑터.
- `ServicePreview.jsx`: 카드 목록 → 상세 페이지, 이미지·상태·필드·긴 설명·전화·외부 링크 표시.
- 구현된 템플릿: `cards`, `detail`.
- 설정만 정의된 템플릿: `table`, `map`, `calendar`, `grouped`, `form`.
- `charts.js`, `Charts.jsx`: 목록에 붙이는 `bar`·`donut` 그래프와 `count` 집계. 2026-09-15 당시에는 Preview 앞 5개 항목 기준이었고 결측도 별도 분류했습니다. 현재 v2의 전체 행 집계는 위 업데이트를 참고합니다.
- 예시 그래프: 소분류별 서비스 수, 결제방법 비율.
- 사용자 요청으로 초기 7개 제한은 절대 규칙이 아니며, 현재 코드는 등록된 7개와 페이지 최대 7개를 허용합니다.

## 2026-09-15 실행한 API 호출

모두 `claude-sonnet-5`, 자동 재시도 없음. 금액은 공식 단가 기준 계산상 추정치입니다.

| 내용 | DB ID | 토큰(입력/출력) | 결과 |
| --- | --- | --- | --- |
| 연결 확인 `OK` | 기록 없음 | 16 / 4 | HTTP 200 |
| 합성 CSV 추론 | `859f056c-c3b2-49d3-b09b-3a6b6682879b` | 1,439 / 1,440 | 코드 블록으로 초기 검증 실패, 이후 DB 원문 재검증 통과 |
| 예시 CSV 앞 5행, 기존 프롬프트 | `e2d11120-3229-43c5-9a37-db5bbc5e4660` | 5,081 / 2,098 | 검증 통과 |
| 예시 CSV 앞 5행, 수정 프롬프트 + JSON 강제 | `ba611416-f034-484c-a99a-c023daa7cc22` | 5,817 / 1,943 | 순수 JSON·검증 통과 |

마지막 결과는 장소/예약서비스 분리와 1:N을 제안했지만, 다섯 번째 행의 다목적구장을 요약에서 테니스장으로 좁히는 오류가 있었습니다. 날짜 컬럼 일부를 엔티티에 배치하지 않고 질문으로 남겼고, 요약과 필드 배치도 완전히 일치하지 않았습니다. JSON 형식 강제는 성공했지만 의미 정확성과 Preview 완전성은 아직 검증되지 않았습니다.
