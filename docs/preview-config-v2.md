# Preview 설정 계약 v2 (구현 기준)

이 문서는 `backend/claude_api_settings/`의 1차 응답 설계를 구현한 계약이다. 신규 추론 요청과 Preview는 v2를 사용한다. 이전 [v1 계약](preview-config.md)의 저장된 호출 기록은 그대로 보존한다.

## 모델 응답

```json
{
  "version": 2,
  "views": [
    {
      "template": "cards",
      "titleColumn": 1,
      "subtitleColumn": 3,
      "fields": [4, 2],
      "charts": [{ "type": "bar", "groupColumn": 2, "aggregate": "count" }]
    },
    { "template": "table", "columns": [1, 3, 2, 4] }
  ]
}
```

- 최상위 키는 `version`, `views`만 허용한다. 버전은 정수 `2`다. `views`는 표시 순서대로 1~7개다.
- 각 뷰의 `template`은 `cards`, `table`, `grouped` 중 하나다. `detail`은 모델의 선택지가 아니며 `map`, `calendar`, `form`도 이번 범위에서 제외한다.
- 모든 컬럼 참조는 CSV 헤더의 위치를 나타내는 **1부터 시작하는 정수**다. 백엔드는 분석 결과의 컬럼 순서와 `columns[].id` 대응을 유지한다. 중복·빈 헤더도 위치로 구분한다.
- 모델 응답에는 화면 제목, 설명, 질문, 페이지 ID, 상세 페이지 참조, 코드, SQL, 계산식, 데이터 행을 넣지 않는다. 화면과 차트 제목 및 필드 이름은 프론트가 템플릿 문구와 CSV 컬럼명으로 정한다.

| 템플릿 | 필수 키 | 선택 키 |
| --- | --- | --- |
| `cards` | `template`, `titleColumn`, `fields` | `subtitleColumn`, `imageColumn`, `badgeColumn`, `charts` |
| `table` | `template`, `columns` | `charts` |
| `grouped` | `template`, `groupColumn`, `titleColumn`, `fields` | `subtitleColumn`, `badgeColumn`, `charts` |

`fields`는 빈 배열을 허용한다. `columns`는 정리 후에도 최소 하나가 필요하다. 각 배열의 순서는 사용자가 보는 순서다. 차트는 뷰당 최대 4개이며 `bar`·`donut`과 `count`만 지원한다. 앞 20행 보기에서는 표시 중인 행을 집계하고, 전체 행 보기에서는 원본 CSV의 모든 데이터 행을 서버에서 집계한다. 두 경우 모두 Claude API를 사용하지 않는다.

목록이나 표의 행을 열면 같은 CSV 행의 **전체 컬럼**을 상세 화면에 표시한다. 이 상세 화면은 설정의 별도 뷰가 아니므로 7개 제한에도 포함하지 않는다. 빈 값과 이름 없는 컬럼의 표시 문구는 프론트 규칙으로 처리한다.

## CSV별 요청과 검증

백엔드는 [예시 스키마](../backend/claude_api_settings/preview_output_schema.example.json)를 복사해서 쓰지 않고 분석 결과로 컬럼 역할별 후보 `enum`을 생성한다. 확실히 부적합한 컬럼만 제외하고, 필수 역할의 후보가 없으면 범위를 넓히거나 해당 템플릿을 선택지에서 뺀다. 선택 역할에 후보가 없으면 그 속성을 빼며 빈 `enum`을 보내지 않는다. 모델이 반환하는 컬럼 번호·템플릿·차트 값은 모두 생성된 `enum`에 속해야 한다.

요청 내용은 명시적인 허용 목록과 크기 상한으로 제한한다. 전체 행의 파싱·통계는 로컬 코드가 수행한다. 예시 행은 `row_number`와 컬럼 순서의 `values`를 함께 보내고, 앞부분에만 치우치지 않은 선택 방식과 잘린 값을 표시한다. 원본 CSV 전체, 파일 경로, 업로드 ID, API 키는 보내지 않는다. 실제 전송 범위와 비용을 사용자에게 보여주고 **호출마다 별도 승인**을 받는다.

새 분석 결과의 `inference_samples`에는 빈 행을 제외한 전체 CSV에서 최대 10행을 보관한다. 앞·중간·뒤 각 2행을 고정하고, 나머지 4행은 파일 내용으로 시드한 난수로 네 구간에서 하나씩 선택한다. 선택 결과는 같은 파일에서 재현되며 CSV 행 순서로 전달한다. 10행 이하인 파일은 각 행을 한 번씩 사용한다. 기존 분석 결과에 이 필드가 없으면 v2 요청 생성은 오류를 반환하므로 재분석 또는 재업로드가 필요하다.

현재 루트 예시 CSV의 실제 로컬 분석 수치와 호출 이력은 [Claude API 전송 예시](claude-api-preview-example.md)에 정리했다. 이 수치는 CSV가 바뀌면 달라지며 새 API 호출 결과가 아니다.

응답 뒤 백엔드는 다음을 결정적으로 수행한다.

1. 배열의 중복 컬럼 번호를 첫 등장만 남기고 제거한다. `fields`에서는 같은 뷰의 제목·부제·이미지·배지·그룹 위치에 이미 표시한 컬럼도 제거한다.
2. 정리된 설정이 동일한 뷰나 차트의 중복 항목을 제거한다. 다른 컬럼 구성의 뷰는 유지한다.
3. 뷰 7개, 차트 4개, 표시 컬럼은 CSV의 최대 200개 범위로 제한한다. 순서는 유지한다.
4. 참조 번호가 이번 CSV에 있는지, 필수 선택과 템플릿별 키가 맞는지, 표에 컬럼이 남았는지 검증한다. 추가 키와 잘못된 타입은 거절한다.

정리 후 유효한 설정을 만들 수 없으면 **이번 CSV의 전체 컬럼을 헤더 순서로 표시하는 기본 표 한 개**를 사용한다. 이 경로는 Claude 재호출을 하지 않는다. 프론트에는 검증된 v2 설정만 전달한다. 스키마가 허용한 선택이 의미상 가장 좋은지는 로컬 검증으로 보장할 수 없으므로 사용자가 Preview에서 확인한다.

`backend/uploads/preview_response_v2.py`의 `prepare_preview_response(raw, report)`가 검증된 `preview`, `used_fallback`, `validation_error`를 반환한다. 오류 사유와 제공자 원문은 호출 기록에 별도로 보존하며, `validation_error`에는 원본 데이터 값을 넣지 않는다.

## 전환 경계

- 백엔드 요청·검증과 프론트 렌더러는 신규 추론에서 v2를 사용한다. 저장된 과거 `ModelCall` 응답은 재해석하거나 모델에 다시 보내지 않는다.
- v2 실제 Claude API 호출은 사용자가 승인한 범위에서 이전에 1회 수행했다. 당시 예시 CSV는 앞 5개 데이터 행만 사용했다. 현재 최대 10행 분산 샘플링으로 새 호출을 하려면 목적·전송 내용·모델·횟수·예상 비용을 다시 확인하고 별도 승인을 받아야 한다.
